## 第 2 页 · 项目背景 & 八个核心问题

**页面标题**

> 三个宿舍，一个值班的人
> —— 我们要替他回答的八句话

**正文**

  哪条已经持续了半小时、处理完到底好了没有。
- **我们把它变成三句心里话**：① 现在什么状况？② 先看哪一间？③ 处理完好了没有？
- **八个核心问题**（一行一句话）：

  | # | 问题 | 答案落在哪 |

  | 1 | 这三间宿舍现在各是什么状况？ | 三张状态卡 + `status` 徽章 |
  | 2 | 三个都异常时，先看哪一个？ | 顶部「当前重点」那一行 + 3D 里的脉冲光圈 |
  | 3 | 它有多严重、已经持续多久了？ | 卡片上的时长、`priority.reason` 里那句人话 |
  | 4 | 处理完到底好了没有？ | 事件表：待处理 → 处理中 → 已恢复 / 未恢复 |
  | 5 | 页面上这个数可信吗？我看的是哪一版？ | 快照带版本号；前端一条阈值都不认识 |
  | 6 | 数据断了、节点失联了，知不知道？ | 卡片上的「已离线 X 分钟」+ core 心跳提示 |
  | 7 | 这一天到底发生了什么？（不是此刻） | 档案 CSV → 单文件 HTML 报告 |
  | 8 | 规则说正常，模型也说正常吗？ | 看板的 Rule-ML 对照表 + 报告的案例分析 |

## 第 3 页 · 系统整体架构、两条数据链

**页面标题**

> 四个进程，一个 Broker，两条链

**正文**

- **没有服务器、没有数据库、没有构建工具。** 前端全静态，后端只有本机一个 Mosquitto。
- **链 ①：实时链（上行 + 下行）**
  采集端（模拟器 / 脚本 / 剧本）→ `publish` 到 `dormmate/v1/nodes/+/telemetry`
  （TCP **1883**，**retained**）→ `core.py` 校验 → 判状态 → 存档案 → 算优先关注
  → 跑事件机 → 跑 ML → 发一帧**全局快照** `dormmate/v1/state` → 浏览器经 WebSocket
  **9001** 拿到 → `dashboard/` `mobile/` `three/` **只订这一条**；
  `web/` 两条都订（快照 + 遥测）—— 它是 M1 那版单节点页，保留原样。
- **链 ②：指令链（反向，人 → core）**
  前端按钮 / 语音 / `send_cmd.py` / 剧本 → `publish` 到 `dormmate/v1/cmd`
  （**不 retained**）→ core 校验 → 只把事件推成「处理中」，**不判恢复**。
- **挂在实时链尾巴上的第三条：档案链（不参与实时）**
  `core.py` 追加写 `data/history.csv`、落盘 `data/events.json` → `analysis/`
  出**单文件 HTML 报告**和 Isolation Forest 模型。
- **一句立命之本**：上行的是「读数」，下行的是「判断」。**新写的三个页面拿到的是算好的结论，
  不是原材料** —— 所以它们永远不会对「这间算不算偏热」有分歧。
- ⚠ **仓库里同时存在两个世界，这一点要主动讲**（被追问才说就晚了）：
  `dashboard/` `mobile/` `three/` **一条阈值都不认识**（`logic.js` 里出现 `18 / 30 / 75`
  会被测试拦下）；而 `web/` 是 **M1 阶段的单节点页**，自己引 `shared/rules.js` 调
  `judgeStatus()` 算状态。**这不是没改干净，是活化石** —— README 里明写了这两者
  「故意不一样」。要证「前端不算」，看的是那三个页面。

**建议配图**

- 主图：**直接用 [`ppt-architecture.svg`](ppt-architecture.svg)**。三个横向色带
  （实时链 / 指令链 / 档案链），方向用颜色区分。这是全篇最重要的一张图。
- 右上角配一张「四个终端窗口并排」的实拍照片（Broker / core / 模拟器 / http），
  让人看到这东西真的只有四个窗口。

## 第 4 页 · 多端分工：为什么不是复制页面

**页面标题**

> 同一个系统的五种出口，不是同一张页面复制五份

**正文**

- **它们各自解决不同的问题，所以长得不一样**：

  | 出口 | 它替人回答的问题 | 保留什么 | 砍掉什么 |
  |---|---|---|---|
  | `dashboard/` 看板 | 全部八个问题 | 三张卡 + 趋势图 + 事件表 + 被拒绝消息 + 内嵌 3D | —— |
  | `mobile/` 手机 | 只答三件事：**谁该管 / 点一下看它 / 按开始处理** | 大卡片 + 迷你列表 + 处理按钮 | 趋势图、事件表、3D、语音 |
  | `three/` 3D | 「哪一间需要关注」让**画面自己说** | 三间房并排 + 悬浮标签 + 脉冲 | 所有数字表格 |
  | `web/` 老页面 | 单节点手动录入 / 摄像头 / 语音指令 | 录入、导 CSV、拍照、语音、**自己算状态** | 多节点、跨端 |
  | `miniapp/` 小程序 | 移动端另一种形态 | 手动录入 + 同一套规则 | （见下方说明） |

- **但「怎么说人话」是同一份代码**：`dashboard/logic.js` 是纯函数库，
  `focusBanner` / `speakLine` / `alertLine` 多端共用 —— 所以**同一帧快照在看板顶部、
  手机大卡片、3D 读数条、念出来的那句话上永远是同一句话**。分叉的时候不会报错，
  那才是最难查的，所以我们从结构上消灭了它。
- **「谁能发焦点」不是按端分的，是按「那个界面看不看得见三间并排」分的**：
  手机发（迷你列表把三间摆一起）、3D 发（三间房并排）、
  **看板不发**（它那块 3D 面板只看一间，「大家看这一间」对它没有意义）。
- ⚠ **小程序要如实说明**：它**不接 MQTT**，是本地规则演示端 —— 微信代码根目录就是
  `miniapp/`，`../shared/rules.js` 进不了包，所以规则抄了第三份。
  我们用 **8211 组温湿度**逐个把它和网页版对齐。

**建议配图**

- **最有说服力的一张**：`dashboard/` `mobile/` `three/` **同一时刻**的截图拼在一起
  —— 同一帧快照的三种呈现。这一张图直接回答「为什么不是复制」。
  **把 `web/` 单独摆在旁边**，标一句「M1 单节点页，自己算状态」——
  这个对照本身就是「分工不是复制」的最好注脚，不要藏。
- 配一张信息分工的对比表（就是上面那张表）。
- 右下角小图：`logic.js` 一个模块、三条箭头指向三个页面的示意图。

## 第 5 页 · D1 · 多节点稳定运行

**页面标题**

> D1 · 三间宿舍同时在线
> —— 一条规则、四种状态、来几个节点画几张卡

**正文**

- **场景**：晚上 20:30，三间宿舍的读数开始跳。
- **判定规则只有一条，而且顺序不可调换**：

  | 顺序 | 条件 | 结果 |
  |---|---|---|
  | 1 | 温度 < 18℃ | 偏冷 |
  | 2 | 否则 温度 ≥ 30℃ | 偏热 |
  | 3 | 否则 湿度 ≥ 75% | 偏湿 |
  | 4 | 其余 | 正常 |

  ⚠ **`31℃ / 80%` 是「偏热」不是「偏湿」** —— 第 2 条先命中。这条规矩最容易被人事后
  改错，所以 Python 侧和 JS 侧**各钉死了一遍**（回归数据：`25/60` 正常、`16/60` 偏冷、
  `31/60` 偏热、`25/80` 偏湿）。
- **多节点成本为零**：订阅的是通配符 `dormmate/v1/nodes/+/telemetry`，每个节点各存一份
  互不相干的状态，**来几个节点画几张卡** —— 节点名单不写在前端任何一个字面量里。
- **刷新页面不用等**：遥测是 retained 的，core 一算完就把快照留在 broker 上，
  页面一订上就有数。（老页面 `web/` 不 retained，刷新要等下一轮 —— 这是**故意不同**的，
  得知道自己在哪个页面上。）
- **守着它的是 2797 条测试**：Python 1230 条 + 十一份 JS 套件 1567 条。

**建议配图**

- 主图：`dashboard/` 三张状态卡的截图 —— 徽章要有**颜色 + 图标**
  （颜色不是唯一编码，色盲也分得清）。
- 左下：`simulator` 终端滚动的 JSON（能看到 `status` 字段）；右下：`core` 终端那三行
  `[数据]`。**两处并排**，证明页面上的字是从这条链上来的。
- 规则表单独放一块，用箭头强调「顺序」。

## 第 6 页 · D2 · 优先关注规则与三组测试案例

**页面标题**

> D2 · 三个都异常，先管哪个？
> —— 规则四步，每一步都给得出理由

**正文**

- **场景**：三间同时异常，值班的人只有一双手。
- **排序四步，命中即停**：

  | 步 | 比什么 | 它赢的时候理由要说什么 |
  |---|---|---|
  | 1 | 连续异常的**持续时长** | 「持续时间最长」 |
  | 2 | 并列时比这一段的**消息条数** | 「持续时间一样长、异常次数最多」 |
  | 3 | 还并列时比**严重度权重** | 「持续时间和次数都一样，但偏湿比偏冷更要紧」 |
  | 4 | 最后按 `nodeId` 字典序 | 保证结果**稳定可复现**，不留随机 |

- **理由必须是真的那一步**：第 2 步赢的那行要提「异常次数最多」，不能顺手写
  「持续时间最长」。这一条由三套剧本逐帧喂给 core 断言，**不用眼睛盯**。
- **三套剧本、三条换人轨迹**（每一套都在逼出不同的决胜步）：

  | 剧本 | 换人轨迹 | 逼出的是哪一步 |
  |---|---|---|
  | `d2_case1` | `→ dorm-b → dorm-c → 空` | 时长决出，靠恢复交接 |
  | `d2_case2` | `dorm-a → dorm-b → dorm-a → dorm-b → dorm-a → 空` | 时长并列比条数，再被更长的接管 |
  | `d2_case3` | `dorm-a → dorm-b → dorm-a → 空` | 时长、条数全平，**严重度**决出 |

- **换人才是新闻**：core 只在**焦点真的换人时**打 `[重点]` 那行 ——
  同一个宿舍一直领先不重复打（时长在涨不是新闻）。

**建议配图**

- 上面那张四步排序表（做成阶梯状）。
- **三套剧本各一张顶部「当前重点」截图**，横向排开 —— 三张截图里被点名的宿舍不同，
  一眼看出规则真的在工作。
- 配一段 `core` 终端 `[重点]` 的原文（能看到括号里那句理由），用小字号，重在「理由是对的」。

## 第 7 页 · D3 · 事件状态机、一次完整事件闭环

**页面标题**

> D3 · 按了「开始处理」，到底好了没有？
> —— 那条不许越的红线

**正文**

- **状态机只有四个状态**：`OPEN`（待处理）→ 收到 `handle` 指令 → `HANDLING`（处理中）
  → 后来连着 3 条正常就 `RECOVERED`（已恢复），连着 3 条异常就 `UNRESOLVED`（未恢复）。
- **红线一句话**：**按一下按钮，不能让事件变成「已恢复」。**
  恢复只能由**后来收到的数据**判出来。
- **它不是靠自觉，是结构上成立的**：
  - `Core.handle_command()` **拿不到节点状态**，它想改也改不了；
  - `event.state = RECOVERED` 这个赋值**只出现在一个函数里**（`_close_recovered()`），
    而那个函数**只被 `observe()` 调**；
  - 另有一组静态检查**拿 `ast` 把函数体抠出来**，盯着这件事。
- **连点很多次呢？** 只多记 N 笔动作，**验证窗口一次都不重置**。重置的话连点几下就能把
  判据一直往后推，事件永远判不出未恢复。
- **一次完整闭环（D3 剧本 14 帧，两幕）**：dorm-b 处理 → **恢复**；
  dorm-c 处理 → **未恢复**。`recovered_at` 保持 `null`（**不是空串** ——
  空串会让「没恢复」和「没记录」长得一样）。

**建议配图**

- 状态机图：**直接用 [`ppt-event-fsm.svg`](ppt-event-fsm.svg)**，红线那一步标红。
- **三张连拍截图**：事件表从「待处理」→「处理中」→「已恢复 / 未恢复」。
  重点让人看到**中间那一步会停住**。
- 小图：`data/events.json` 里一条事件的片段（能看到 `state` / `recovered_at` / 验证计数）。
- 代码截图：`ast` 那组静态检查的一小段 —— 「红线是结构上成立的」这句话要靠它落地。

## 第 8 页 · E1 · 3D 数字空间

**页面标题**

> E1 · 让画面自己说出「该看哪一间」

**正文**

- **动机**：数字看板得先**读一遍**才知道该看哪间。3D 想把这一步省掉 ——
  三间房并排摆在一个世界里，「谁需要关注」由画面自己说。
- **会动的东西只有四样，各跟着一条不同的线**：

  | 画面里 | 跟着谁 | 数据从哪来 |
  |---|---|---|
  | 地板颜色 / 窗户 | 环境状态（正常/偏冷/偏热/偏湿） | 快照 `nodes[].status` |
  | 风扇转不转 | 环境状态（偏热）**或**事件状态（处理中） | 前者 `status`，后者 `events[].state` |
  | 脉冲光圈 | 谁是当前重点 | 快照 `priority` |
  | 相机飞过去 | 焦点是谁 | 快照 `focus` |

- **脉冲和焦点是两件事**：脉冲说「这三间里最该管这间」（不动视角），
  相机飞过去说「现在在看这间」（不动画面）。两个都不做，人还是得先读一遍数字。
- **三个坑（都是「控制台一条错都没有」那种）**：
  1. **一盏灯没法同时是三种颜色** → 灯固定，状态只落在**长在那间房自己身上**的零件上
     （地板色 / 窗扇 / 风扇），跑不出那间房；
  2. **标签层没设 `pointer-events: none` 会吃掉所有鼠标事件** → 表现是「点房间没反应」，
     **控制台无任何报错**；
  3. **相机每帧都得重调 `lookAt`** → 只改位置不改朝向，画面挪了一下但没转过去，同样不报错。
- **17 个变异逐个塞回源码，17 个全被抓住、0 个存活**，跑完逐字节还原比对 sha256。
  191 条测试盯着这个页面。

## 第 9 页 · E2 · 多模态语音 + 拍照的完整交互链

**页面标题**

> E2 · 手上拿着东西的时候
> —— 一句话走完一条链：说 → 认 → 做 → 回帧确认

**正文**

- **场景**：值班的人刚搬完东西、手上不空，不想碰键盘。
- **四句固定指令，顺序就是优先级**（关键词用「**包含**」判断 —— 识别引擎会把语气词和
  标点一起吐出来，「朗读一下。」这样整句比对永远匹配不上）：

  | 说什么 | 干什么 | 关键设计 |
  |---|---|---|
  | 「查看 dorm-b」 | 发一条 `focus` 指令 | **本地不动镜头** —— 等 core 发回的新快照说了算 |
  | 「记录现场」 | 摄像头拍照 + 打水印 | 水印第一行是**这条证据的身份**：`宿舍 · 事件编号 · 时刻` |
  | 「朗读状态」 | TTS 念出当前状况 | 念哪句由 `logic.js` 的 `speakLine` **现算**，页面一个字都不拼 |
  | 「开始处理」 | 发一条 `handle` 指令 | 和按钮走**同一条**指令链，同样不判恢复 |

- **完整链路（本页的核心图）**：
  `麦克风 → 浏览器 ASR（Chrome 走云端识别，要联网）→ 词表路由 → 四件事之一

- **一处必须讲清的诚实设计**：**照片本身只留在浏览器**（画布里的 base64，页面上显示那一张），

  → 所以**确认方式是「下一帧快照里 `cameraCount` 变大了」**。指令没发出去、或者 core 拒收
  （那间此刻没有未结案的事件），屏幕上**不许**写「已登记」。这是全项目最不该出现的一类假话。
- ⚠ **限制要提前说**：麦克风、摄像头、语音识别都只在**安全上下文**里可用 ——
  `localhost` ✓，`file://` ✗，**手机扫码走局域网 IP 的 http 也不安全** ✗。演示要老实用本机。

## 第 10 页 · E3 · Web–移动端跨端协同联动

**页面标题**

> E3 · 在手机上点一下，大屏跟着切过去

**正文**

- **场景**：值班的人拿着手机在楼道里，值班室那块大屏上大家在看。
  他在手机上点了 `dorm-b`，三个屏幕同时跟过去。
- **一条 `focus` 指令走完全程**：

  ```
  手机点一下 dorm-b
     └ publish dormmate/v1/cmd  {"nodeId":"dorm-b","action":"focus","source":"mobile"}
       （不 retained：指令是一次性的，留在 broker 上等于下次起 core 时凭空切一次焦点）
       ▼
  core 校验 → 记进焦点 → 终端：[指令] dorm-b focus（mobile）-> 接受：焦点切到 dorm-b
       ▼
  publish dormmate/v1/state（retained）  focus: {nodeId, by:"mobile", at}
       ├─▶ mobile      大卡片换成 dorm-b、列表那一行点亮
       ├─▶ dashboard   顶栏标签变「跨端焦点」、趋势图切过去
       └─▶ three       场景切到 dorm-b
  ```

- **红线（和 D3 那条是同一类）**：**点完那一刻页面上一个字都不改。** 手机端 `tapNode`
  只做两件事 —— 把指令发出去、把说明写出来。焦点归谁要**等 core 发回来的新快照**。
  本地先把那一行点亮就是「伪造同步」，而题目里点名禁止的正是这件事。
  所以移动端**连一个输入框都没有**，有测试盯着。
- **「谁能发焦点」的判据不是端，是「那个界面看不看得见三间并排」**
  （手机发、3D 发、看板不发）—— 判据看得见、可查，而不是一句关于人在干什么的推测。
- **跟随的优先级也得说清**：**焦点变了就跟着切，跟过之后就不再抢** ——
  比的是「这个目标跟过了没有」，不是「这一帧里有没有焦点」。
  不然用户点到别处看，下一条一模一样的快照又会把他拽回去。

## 第 11 页 · D4 · 一次真实故障：制造 → 定位 → 修复

**页面标题**

> D4 · 演示到一半，Broker 挂了
> —— 三类故障的现场记录

**正文**

- **每一类都是一个完整的五步记录**：制造 → 现象 → 定位 → **手动修复** → 验证恢复。

  | 故障 | 怎么制造 | 最直接的定位手段 |
  |---|---|---|
  | ① **停掉 Broker** | 终端 1 里 `Ctrl+C` | 三个页面右上角翻成「未连接 / 重连中…」；core 打**一行**断开；`netstat` 上 1883/9001 没了 |
  | ② **Topic 写错 / 对不上** | `…/telemetery`（少一个 `y`）、`…/v2/…`、或 topic 与报文里的 `nodeId` 不一致 | 前两种：core **什么也没有**，MQTTX 订 `v1/#` 能看见那条孤儿消息。第三种：core 打 `[拒绝]` 并写明两边不一致 |
  | ③ **非法报文** | 一条脚本发全九类（非法 JSON / 缺字段 / 未知节点 / 数值离谱 / …） | `inject_faults` 自己那张表：逐条写着「core 拦住了没有、理由对不对」——**core 没在跑时那张表全红，它不会假装绿** |

- **现场最反直觉的一处（这一页的高潮）**：把 broker 停掉再起回来，
  - 三个页面右上角**自己回到「已连接」**了；
  - 但卡片**冻在最后一帧**，一动不动；
  - 只有 core 心跳那条说「core 没声了」。

  **为什么？四个进程里只有 `core.py` 不会自己重连。** 前端走 mqtt.js（自带 2 秒重连），
  模拟器走 `loop_start()`（内部是带自动重连的 `loop_forever()`），而 core 的主循环是
  **轮询式**的 `while True: client.loop(timeout=0.5)`，paho 的自动重连
  **只在 `loop_forever()` 里**。
  → **「页面已连接 + 数字不动」这个组合，答案就是 core 没回来。** 去 core 那个终端重启一遍。
  D4 的要求本来就是「不需要写自动修复」，手动修复是修复动作的一部分，不是漏做。

- **还有一类更常见、题干里没写**：**core 自己停了**。判断方法**不是**「页面有没有数据」——
  快照是 retained 的，core 死了页面照样有数据、而且**长得一模一样**；
  唯一可靠的判据是**页面顶部那条 core 心跳**：超过 15 秒没有新帧（`staleAfterSec`）
  就说「core 没声了」。

**建议配图**

- **首选截图**：「页面右上角写着『已连接』、数字一动不动」那张 ——
  它一张图就把上面那段话讲完了。
- 配 `netstat` 故障前/后的对比（有 `ESTABLISHED` vs 只有 `LISTENING`）。
- 配 `inject_faults` 终端那张九条表（拦住了 / 理由对不对）。
- 右下角小图：**两条判据的对照** —— 「节点失联」看卡片（30 秒超时）、
  「core 死了」看顶部心跳（15 秒没新帧）。

## 第 12 页 · D5 · Rule 与 ML 对照分析案例

**页面标题**

> D5 · 规则说正常，模型也说正常吗？
> —— 两个方向的不一致，都要点出来

**正文**

- **两条链，同一套判据**：
  - **离线链**：`analysis/ml.py` → 出一份报告，进 `report/`；
  - **在线链**：core 收到每条遥测就跑一次**该宿舍自己的**模型 → 写进档案第 6 列
    `ml_label` 和第 10 列 `agree`，同时进快照给看板。
- **规则和模型问的不是同一个问题**：规则问「**越没越线**」（阈值），
  模型问「**像不像这间宿舍平时**」（在温湿度两维上切）。所以两边分家是正常的，
  **我们要做的是把它显式地摆出来**。
- **构造案例（可复现）**：`data/constructed_samples.json` 里几条样本 `source` 无条件写
  `constructed`，**训练时一律跳过**。
  ⚠ 不跳的话，那些极端值会被当常态训进去，之后模型判它们「正常」——
  **案例静默地复现不出来**。跳过判据全项目只有一处。
- **词表各有各的家**（这一条讲出来很加分）：

  | 位置 | 值 |
  |---|---|
  | `predict()` 的返回值 | `1` / `-1` |
  | 档案第 6 列 + 快照 `mlLabel` | `normal` / `abnormal` |
  | 报告里给人看的 | 「接近历史常态 / 与历史明显不同」 |
  | 档案第 10 列 `agree` | `yes` / `no` |

  ⚠ `agree` **不能写 Python 布尔** —— 落盘那层的 `_cell()` 把 `bool` 当缺值打成空串，
  写进去整格会消失，于是「**没判**」和「**判了不一致**」在档案里长得一模一样。
  **留空 = 没判，不是判成正常。**
- **一条实测（本页最硬的一处）**：sklearn 1.9.1 的 `predict` 是拿 `decision_function < 0`
  切的，**和 `offset_`（-0.5）无关**；如果改用 `score_samples < 0`，在同一份真数据上会
  **差 1/6 行**。两套口径并存，两条 ML 链就会在同一行上给出不同结论 ——
  所以**两条链统一只用 `predict()`**，并有一条测试钉死这件事。
- **边界（题目给的，不许越）**：不做 train/test 划分、**不算 accuracy / F1**、
  **不调参去刻意制造不一致**。

- 左：报告里 **「Rule-ML 对比」表 + 下方的「案例分析」板块**同屏 ——
  能看到「是 / 不是」**两个方向都高亮**。
- 右：看板的「实时 Rule-ML 对照」表（构造样本那几行）。
- 下：`train_iforest` 终端逐节点汇总（能看到 `constructedSkipped` 那一列不是 0）。

## 第 13 页 · 自主设计决策、亮点与 Open Enhancement

**页面标题**

> 我们自己拍板的地方，和往哪走

**正文**

**A. 自主设计决策**（每一条都有「为什么」，不是随手选的）

| 决定 | 为什么 |
|---|---|
| **没有服务器、没有数据库** | 一个 Broker + 四个进程就够，前端纯静态不打包 —— 复现门槛压到最低（解压完照着五步走） |
| **`core.py` 是唯一业务大脑** | 前端**一条阈值都不认识**（`logic.js` 里不许出现 `18 / 30 / 75`，有测试盯着）。前端再算一遍就是同一件事写两份，两边迟早说两套话 |
| **三份「只有一处」** | 规则实现、topic 字符串、快照形状 —— 第二份一出现就是 bug，每个都有测试 |
| **判定顺序不可调换** | `31/80` 是偏热不是偏湿，Python 与 JS 两侧各钉死一遍 |
| **`staleAfterSec` 由 core 算好放进快照** | 三个前端不能各算各的 —— 它们算出不同答案时会**静默地**给出互相矛盾的提示 |
| **retained 的取舍** | 遥测和快照 retained（刷新即见）；`cmd` **不** retained（否则下次起 core 凭空把事件推进「处理中」）；`reject` **不** retained（坏消息不许留在 broker 上） |
| **部分更新，不整份替换** | 前端只遍历快照里提到的节点 —— **「缺数据」和「正常」是两件事**，显示层没资格替谁做主 |

**B. 亮点**

- **红线是结构上成立的，不是靠自觉**：指令处理函数**拿不到节点状态**；
  「置为已恢复」那个赋值**只出现在一个函数里**；还有一组用 `ast` 抠源码的静态检查盯着。
- **测试是靠变异验证过的**：2797 条（Python 1230 + JS 1567），而且大量场景是
  **把 bug 真的塞回源码**，确认被抓住、跑完逐字节还原。3D 那块 17 个变异 0 存活。
- **每个页面都会「说真话」**：core 没跑时卡片区写「先起 core.py」而不是灰着不说话；
  指令没发出去就**明说没发出去**；照片没被 core 登记就不写「已登记」。

**C. Open Enhancement 拓展**（这些不是没想到，是刻意留的）

1. **core 自动重连** —— 约 6 行：主循环里 `client.loop()` 返回非 0 时调一次
   `client.reconnect()`。D4 明确不要求，`on_connect` 那边的重新订阅逻辑**早就写好了**。
2. **`history.csv` 轮转 / 归档** —— 现在只追加、无上限，一天约 5 万行。
   档案一条都不许丢，所以得做归档而不是截断。
3. **报文乱序保护** —— 现在 `latest` 一律被**最后收到**的顶掉，比的是到达顺序而不是报文时间。
   真正的防线目前是剧本里同节点时间必须递增。
4. **图片真的上传与存储** —— 现在只有元数据过 MQTT，图留在浏览器。
5. **规则三处实现 → 单源生成** —— 网页 / Python / 小程序各一份，靠 8211 组数据对拍保证一致；
   更好的做法是从一份源生成三份。
6. **ML 从「对照」推进到「告警」** —— 需要 train/test 划分和阈值标定，当前**刻意不做**。

**建议配图**

- 左上：那张「决定 / 为什么」表（用两列，别塞第三列）。
- 右上：测试规模的柱状图（Python 1230 / JS 1567，再按套件拆开）。
- 中下：`ast` 静态检查的一小段代码截图 —— 「红线是结构上成立的」这句要靠它落地。
- 底部：一条**拓展路线图**（六个箭头，1~2 标「小改动」，3~6 标「下一阶段」）。
