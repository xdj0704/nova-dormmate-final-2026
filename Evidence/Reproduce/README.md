这份说的是**你做完之后，做成了什么样** —— 一格一格填，填完这份文件就是

1. 先通读 `README.md` 的「交叉复现手册」第 1、4 节（项目讲什么、五步启动顺序）。

   |---|---|
   | 抄下你看到的**原文** | 复现成功。原文比"成功了"有用得多 |
   | 写下**报错原文** | 复现失败。报错原文是本文件最有价值的部分 |

这一步把「链路是通的」从感觉变成**两个能对上的证据**。

## 5. 故障演练记录（D4）

> **全程在能重启的前提下做**，别在正在演示的系统上做。
> 三类故障的详细操作手册在 `README.md` 的 `## Phase9 D4` 那一节。

### 故障 ①：停掉 Broker

| 步骤 | 动作 | 你填 |
|---|---|---|
| 制造 | 终端 1 按 Ctrl+C | |
| **现象 1** | 三个前端右上角翻成「未连接 / 重连中…」 | |
| **现象 2** | core 终端打**一行** `[连接] 与 broker 断开：…`，**然后再没有任何反应** | |
| **现象 3** | `netstat -ano \| findstr "1883 9001"` 没有输出 | |
| 恢复第 ① 步 | 重新 `mosquitto -c mosquitto/dormmate.conf -v` | |
| 恢复第 ② 步 | **重启 core**（Ctrl+C，再 `py -3.14 core.py`） | |

> ⚠ **「重启 core」这一步不是啰嗦，是必须的 —— 四个进程里只有 core 不会自己重连。**
> 主循环是 `while True: client.loop(timeout=0.5)`，而 paho 的自动重连只在
> `loop_forever()` 里。前端页面（mqtt.js `reconnectPeriod: 2000`）和模拟器
> （`loop_start()`）都会自己连回来。
>
> **只把 broker 起回来的现场长这样**：页面右上角写着**「已连接」**、数字**一动不动**、

## 附：这份记录为什么长这样

- **每一格都要抄原文**，是因为「成功了」这三个字无法证伪，而一行报错可以。
- **「未做」是合法答案**。这套记录要的是实情，不是满分。
- **每条判定都绑一句可观察的判据**（"看到左边那行字才打勾"），
  是为了让打勾这件事本身也可复核 —— 换个人来看，应该能得出同样的勾。
- 手册里的**阈值、topic、字段名一律不在这份记录里重写**，只写「去哪儿看」。
  抄来抄去的东西，改了源头这里就会变成假话。
